## 问题清单

### 🔴 P0 — `GetRepresentativeB` 使用 `max` 对异常值零容忍

**文件：** `Services/Rail/Core/StandardRailProfileSolver.cs:158-167`

**现状：**
```csharp
double best = double.NegativeInfinity;
for (int index = 0; index < representativeSectionPoints.Count; index++)
{
    double candidate = point.Y - k * point.X;
    if (candidate > best) best = candidate;
}
```

**问题：**
这是整个打磨深度计算链中最脆弱的一环。即使前面做了多层异常值过滤（MAD、滑动窗口），只要代表廓形中混入**1个**未被过滤的飞点（如镜面反射噪点、传感器跳变），`max` 操作就会直接返回该飞点的截距值，导致打磨深度严重偏大。

**后果：**
- 打磨过量 → 轨面损伤 → 安全隐患
- 测量重复性差 → 同一位置多次测量结果波动大

**修复建议：**

```csharp
public static double GetRepresentativeB(double k, IReadOnlyList<RailProfilePoint> points)
{
    if (double.IsNaN(k) || double.IsInfinity(k))
        throw new ArgumentException("参数 k 必须为有限数值。", nameof(k));
    if (points == null)
        throw new ArgumentNullException(nameof(points));
    if (points.Count == 0)
        throw new InvalidOperationException("代表截面点集不能为空。");

    // 方案A: 取前0.5%点的平均值（推荐，兼顾精度与抗噪）
    var candidates = new double[points.Count];
    for (int i = 0; i < points.Count; i++)
        candidates[i] = points[i].Y - k * points[i].X;

    int topCount = Math.Max(1, points.Count / 200); // 前0.5%
    int thresholdIndex = candidates.Length - topCount;
    double threshold = QuickSelect.SelectKthSmallest(candidates, thresholdIndex);

    double sum = 0.0;
    int count = 0;
    for (int i = 0; i < candidates.Length; i++)
    {
        if (candidates[i] >= threshold)
        {
            sum += candidates[i];
            count++;
            if (count >= topCount) break;
        }
    }
    return sum / count;

    // 方案B: 取 P99.5 分位数（更保守，改动更小）
    // int topIndex = Math.Max(0, (int)(points.Count * 0.995));
    // return QuickSelect.SelectKthSmallest(candidates, topIndex);
}
```

**验证标准：**
- 人工注入1~2个飞点（Y值偏移 2mm），计算结果偏差 < 0.02mm
- 正常数据计算结果与原 `max` 方法偏差 < 0.01mm

### 🟡 P1 — 截面分组容差 `1e-7` 与真实传感器物理分辨率不匹配

**文件：** `Services/Rail/PointCloudRepresentativeProfileService.cs`

**现状：**
```csharp
private const double Tolerance = 1e-7; // 约 0.0000001 mm

// 第335行
if (currentSection == null || Math.Abs(point.Y - currentY) > Tolerance)
{
    // 新截面
}
```

**问题：**
廓形仪的 Y 方向物理分辨率通常在 **0.2 ~ 1.0 mm** 量级，远大于 `1e-7`。由于传感器的微小噪声，同一物理截面内的点 Y 坐标会有 `±0.001 ~ 0.01 mm` 的波动。使用 `1e-7` 容差会导致：
- 同一物理截面被拆成多个"伪截面"
- 伪截面点极少（可能1~2个），导致 `NormalizeSection` 退化
- `BuildValidSections` 中会过滤掉点数 < 2 的截面，浪费数据

**修复建议：**

```csharp
// 使用与传感器物理分辨率匹配的容差
private const double DefaultYResolutionMm = 0.5; // 廓形仪典型Y分辨率，可配置

private static List<List<PointCloudPoint3D>> SplitSectionsByY(
    IReadOnlyList<PointCloudPoint3D> points, 
    double yTolerance = DefaultYResolutionMm * 0.5)
{
    // ... 排序逻辑不变 ...
    
    for (int i = 0; i < sortedPoints.Count; i++)
    {
        PointCloudPoint3D point = sortedPoints[i];
        if (currentSection == null || Math.Abs(point.Y - currentY) > yTolerance)
        {
            currentSection = new List<PointCloudPoint3D>();
            sections.Add(currentSection);
            currentY = point.Y;
        }
        currentSection.Add(point);
    }
    // ...
}
```

**注意事项：**
- 容差值建议通过 `PointCloudCaptureSettings` 透传，支持不同廓形仪型号配置
- 应同时保留 `Tolerance` 用于数学舍入判断（如 `Math.Abs(x1 - x2) < Tolerance`），与物理分组容差分开

### 🟡 P1 — 代表Y使用简单算术平均，受采样密度偏差影响

**文件：** `Services/Rail/PointCloudRepresentativeProfileService.cs:154-173`

**现状：**
```csharp
private static double ResolveAverageY(IReadOnlyList<PointCloudPoint3D> points)
{
    var uniqueYSet = new HashSet<double>();
    double sumY = 0.0;
    for (int i = 0; i < points.Count; i++)
    {
        double y = points[i].Y;
        if (uniqueYSet.Add(y))
            sumY += y;
    }
    return sumY / uniqueYSet.Count;
}
```

**问题：**
如果廓形仪在 Y 方向扫描不均匀（中间采样密、两端疏），算术平均会使代表Y向密集区偏移。但代表Y是用来确定"选哪个截面作为参考"的——偏离中心意味着选择了偏心的截面。

**修复建议：**

```csharp
private static double ResolveAverageY(IReadOnlyList<PointCloudPoint3D> points)
{
    double yMin = double.MaxValue, yMax = double.MinValue;
    for (int i = 0; i < points.Count; i++)
    {
        double y = points[i].Y;
        if (y < yMin) yMin = y;
        if (y > yMax) yMax = y;
    }
    // 使用Y范围中位数代替算术平均，不受采样密度偏差影响
    return (yMin + yMax) / 2.0;
}
```

**或者用中位数：**

```csharp
var sortedUniqueY = points.Select(p => p.Y).Distinct().OrderBy(y => y).ToArray();
return sortedUniqueY[sortedUniqueY.Length / 2]; // 中位数Y
```

### 🟡 P1 — 网格间距对异常截面过于敏感

**文件：** `Services/Rail/PointCloudRepresentativeProfileService.cs:388-408`

**现状：**
```csharp
private static double ResolveTypicalXStep(IReadOnlyList<double> xIntervals)
{
    // 收集所有截面的所有相邻X间距到一个列表
    // 取该列表的中位数作为网格步长
}
```

**问题：**
所有截面的所有间距混在一起取中位数。如果某个退化截面（比如传感器噪声产生的）只有2个点，间距异常大或小，会污染全局统计。

**修复建议：**

```csharp
private static double ResolveTypicalXStep(List<List<SectionPoint>> sections)
{
    var sectionMedianSteps = new List<double>();
    foreach (var section in sections)
    {
        if (section.Count < 2) continue;
        var steps = new List<double>();
        for (int i = 1; i < section.Count; i++)
        {
            double step = section[i].X - section[i - 1].X;
            if (step > Tolerance) steps.Add(step);
        }
        if (steps.Count > 0)
            sectionMedianSteps.Add(Median(steps)); // 每截面先取中位数
    }
    if (sectionMedianSteps.Count == 0)
        throw new RepresentativeProfileExtractionException("无法确定有效网格步长。");
    return Median(sectionMedianSteps); // 再取截面间中位数
}
```

### 🟢 P2 — 最低有效截面数 `MinValidSectionCount = 2` 偏低

**文件：** `Services/Rail/PointCloudRepresentativeProfileService.cs:20`

**现状：**
```csharp
private const int MinValidSectionCount = 2;
```

**问题：**
2个截面就够算平均廓形——数学上可以，工程上太危险。任意一个截面有异常，平均廓形就不可靠。实际廓形仪一帧通常能产生 10~50 个有效截面。

**修复建议：**

```csharp
// 提高到5，低于此阈值意味着传感器数据质量异常
private const int MinValidSectionCount = 5;
```

同时在提取结果中增加警告信息，当截面数低于某个健康阈值（如 10）时通知调用方。

### 🟢 P2 — 异常值过滤窗口大小固定，对小廓形不适用

**文件：** `Services/Rail/Processing/RepresentativeProfilePointProcessor.cs:30-31`

**现状：**
```csharp
private const int OutlierFilterWindowSize = 15;
private const int MinNeighborCount = 6;
```

**问题：**
窗口大小固定为15个点。如果代表廓形点数较少（比如经过极端裁剪后只有30个点），窗口覆盖了一半的点，局部直线拟合会过于平滑，漏掉真实的小尺度特征。

**修复建议：**

```csharp
private static int ResolveWindowSize(int totalPoints)
{
    // 窗口大小 = min(15, 总点数的 20%)
    // 确保窗口不至于覆盖过大比例
    int adaptiveWindow = Math.Max(5, totalPoints / 5);
    return Math.Min(15, adaptiveWindow);
}
```

## 回归验证方法

修复后建议使用以下方法验证：

1. **正常数据一致性测试**：取10组历史CSV数据，修复前后偏差 < 0.01mm
2. **飞点注入测试**：在正常数据中随机插入1~3个 Y 偏移 2mm 的噪点，修复后偏差 < 0.02mm（原实现 > 2mm）
3. **边界截面测试**：使用截面数 = 3~5 的数据，验证不报错且结果合理
4. **空数据/全零点测试**：验证异常抛出逻辑不变
